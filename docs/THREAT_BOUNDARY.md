# Threat boundary and limitations

The replay environment consists of four pure Python functions behind explicit tool-name branches. No dispatch extension point exists. The core does not import filesystem, subprocess, networking, provider SDKs or serialization libraries. It cannot execute trace-provided commands or follow trace-provided URLs and paths. The CLI reads only the input filenames its caller supplies, and the receipt exporter writes only the caller's explicit output filename, exclusively.

This is a trusted local diagnostic tool for wholly synthetic traces. It is not a hardened sandbox for hostile Python, a real-agent capture system, or a general secrets scrubber. Do not feed it real credentials, personal information, proprietary sessions or private research. The parser bounds input bytes, string and integer sizes, nesting and events, but callers of low-level Python functions remain responsible for passing bounded data and controlling their own process resources. Direct CLI file paths can point to devices or other unsuitable local files; use ordinary synthetic JSON files.

Reference validation replays allowlisted stubs and checks the recorded truth and transitions. Observed traces are compared to that validated reference as data. A tool or input change is evidence of a regression against this reference, not a claim about how an actual external tool would behave. Payload values are excluded from divergence reports, but synthetic reference step IDs remain visible. Redaction replaces only the exact synthetic marker; it does not detect arbitrary secrets.

Only timestamp, duration_ms and request_id inside explicitly designated metadata objects are ignored. Concurrency, real clocks, stochastic model outputs, external tool versions, network behavior, retries with hidden side effects, and nondeterministic ordering are unsupported. Arrays and event order remain meaningful. Distinct numerically equal JSON types remain distinct. Failure taxonomy and non-cascade decisions are deliberately narrow and documented in SPEC.

The benchmark tests declared single-fault mutations. Combined-fault behavior has small ordinary unit tests, not exhaustive combinatorial evaluation. Synthetic case sensitivity, zero false alarms and perfect declared-mutation detection do not establish production reliability, coverage of every possible regression, or safety of an agent system. Aggregate output cannot reconstruct each trial's divergence records. Repeated report equality was planned inside the batch; aggregate hashing has a separate, narrower export meaning.

Operational CPU, memory and wall limits belong to the external supervisor. Conservative combined process high-water memory is not simultaneous RSS or a hard allocation cap. The measured CPU field is a lower bound before final receipt/database closeout; charged CPU is a reserved accounting amount. Neither the library nor its AST review should be described as an operating-system security boundary.
